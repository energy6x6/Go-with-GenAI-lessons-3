# Промпт для виокремлення інтерфейсу (Розділ 2)

## Роль

Ти — досвідчений розробник Go. Виконай рефакторинг `OrderService`
так, щоб сервіс можна було тестувати без реальної бази даних.

## Контекст

За умовою завдання `OrderService` безпосередньо залежить від `*sql.DB`. Цю залежність
ілюструє такий код:

```go
package orders

import "database/sql"

type OrderService struct {
    db *sql.DB
}

func (s *OrderService) PlaceOrder(orderID string, amount float64) error {
    _, err := s.db.Exec("INSERT INTO orders (id, amount) VALUES (?, ?)", orderID, amount)
    return err
}
```

У навчальному репозиторії файл `orders/orders.go` вже частково підготовлено
до рефакторингу: у ньому визначено інтерфейс `OrderStore` з методом
`Exec(query string, args ...any) error` та конструктор `NewOrderService`.
Результат має бути сумісним із цим каркасом і готовими тестами
з файлу `orders/orders_test.go`.

## Завдання

1. Виокреми мінімальний інтерфейс `OrderStore` на стороні споживача,
   залишивши лише операцію, яку використовує `PlaceOrder`. Поясни вибір
   відповідно до принципу «чим більший інтерфейс, тим слабша абстракція».
2. Зміни `OrderService` так, щоб він залежав від інтерфейсу `OrderStore`
   й отримував його реалізацію через конструктор `NewOrderService`.
   Збережи поведінку `PlaceOrder`: виконання запиту з аргументами
   `orderID` і `amount` та повернення помилки.
3. Згенеруй мок-реалізацію `OrderStore` для тестів без реальної бази даних.
   Мок має зберігати кількість викликів, запит і аргументи та повертати
   помилку, задану в тесті.

## Обмеження

- Використовуй Go 1.27.1, стандартну бібліотеку та форматування `gofmt`.
- Не додавай зайвих методів до інтерфейсу, зовнішніх бібліотек або підключення до БД.
- Передавай значення як параметри SQL-запиту. Не змінюй готові автотести.
- Збережи навчальну сигнатуру методу `Exec`, який повертає лише `error`. Врахуй,
  що реальний `sql.DB.Exec` повертає `(sql.Result, error)`, тому `*sql.DB`
   не реалізує цей спрощений інтерфейс безпосередньо.

## Формат відповіді

Поверни коротке пояснення та три блоки коду Go: інтерфейс `OrderStore`,
сервіс із конструктором і мок для тестів. Не додавай демонстраційну програму.
